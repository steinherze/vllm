EmbeddingGemma2 text LoRA: implementation and validation record

Publication status (checked 2026-11-05)

No new PR was opened. The existing open PR #60632 by

https://github.com/vllm-project/vllm/pull/60632
It is not a draft, is not merged, and currently has head 04497da8a89d42dc53c317088ab285a0e335c72a.
AGENTS.md prohibits opening another PR addressing the same fix.
This branch preserves the independently implemented patch and its validation.

Our additional scope is strict adapter-target validation, negative checkpoint
coverage, reproducible two-adapter PEFT parity and automatic CI selection of the
new tests. The existing PR routes text LoRA with get_mm_mapping(); this patch
uses an opt-in full-match filter for wrapping and checkpoint loading. These
extras do not justify a second PR advertising the same model support. Any
future contribution must be coordinated and scoped around nonduplicated work.

Implementation

- EmbeddingGemma2Model implements SupportsLoRA.
- Supported text targets: q_proj, k_proj, v_proj, o_proj, gate_proj, up_proj,
  down_proj under language_model.layers.*.
- Existing qkv_proj and gate_up_proj mappings preserve separate PEFT deltas.
  Weight names already match vLLM paths; no renaming was added.
- Optional lora_module_filter on SupportsLoRA restricts wrapping and rejects
  checkpoint weights outside the model's supported scope before application.
- Vision/audio towers, connectors, PLE, embedding_projection, embedding layers,
  modules_to_save and saved base_layer weights are rejected for this model.
- enable_tower_connector_lora=True is rejected explicitly.
- Other model classes keep the existing default behavior (filter=None).
- No scheduler or pooling/model-runner implementation was changed.
- Rendered docs include the supported targets, limitations and LLM.embed example.
- Existing test suites and Buildkite dependencies were extended.

Two deterministic synthetic PEFT adapters: seeds 42 and 43, r=8, lora_alpha=8,
bias=none, init_lora_weights=False, modules_to_save=None.
Each adapter has 336 nonzero tensors: 24 layers x 7 projections x A/B.
Target regex:
  language_model\.layers\.\d+\.(self_attn|mlp)\.(q_proj|k_proj|v_proj|o_proj|gate_proj|up_proj|down_proj)
Tensor names follow:
  base_model.model.language_model.layers.<layer>.<self_attn|mlp>.<projection>.lora_<A|B>.weight
These are mechanical test adapters, not trained retrieval adapters.

Preprocessing uses the same tokenizer IDs (14, 15, 9 and 523 tokens), mean
pooling of projected last_hidden_state with float32 accumulation, then L2
normalization. The 523-token text crosses the sliding-window boundary.
Cosine threshold >=0.999 reuses the existing model suite's BF16 tolerance;
different attention/reduction orders accumulate rounding across 24 layers.
